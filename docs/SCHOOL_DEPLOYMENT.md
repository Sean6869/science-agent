# 管理员、教师与学生

## Railway 部署

1. 为应用挂载 Volume 到 `/data`，保留现有卷。使用仓库 Dockerfile，Node.js 24，单副本，健康检查 `/health`。
2. 设置 `ADMIN_USERNAME`、`ADMIN_PASSWORD`（至少12位）。升级已有服务时，将旧变量 TEACHER_USERNAME、TEACHER_PASSWORD 分别改名为 ADMIN_USERNAME、ADMIN_PASSWORD，值保持不变，然后删除旧变量。应用只读取 ADMIN_* 管理员配置。
3. 保留 `DEEPSEEK_API_KEY` 等模型变量。部署后原初始教师账号自动升级为管理员，账号、密码、学生、成绩和对话保持不变。

Railway 自动注入 `RAILWAY_VOLUME_MOUNT_PATH`。缺少实际挂载卷时应用拒绝启动，不要手工伪造该变量。每次启动会将 ADMIN_USERNAME、ADMIN_PASSWORD 同步到部署管理员。修改后重新部署即可更换管理员登录信息，保留同一管理员身份及全部教学数据；变更账号密码时会注销该管理员旧会话。配置与教师或学生账号重名时拒绝启动，避免覆盖其他身份。

## 身份与班级

- 三种身份共用登录页，页头分别显示管理员端、教师端、学生端。
- 教师点击“教师注册”，填写姓名、账号和密码。注册只创建教师身份，不能申请管理员权限。
- 每位教师可管理多个班级，班级名称来自学生名单。同名班级不会自动共享学生；服务器核验班级ID及教师归属。
- 教师只能管理本班学生、测验成绩、AI对话和导出文件。管理员可按班级查看全部数据，并在“教师账号”查看或重置教师密码、编辑或停用教师。
- 升级前的学生按原班级迁入管理员管理的班级，不会自动分配给后来注册的同名班级。

## Excel 导入与导出

- 模板首行：`姓名`、`性别`、`年龄`、`班级`。先删除模板示例行，再填写真实学生；年龄可留空，性别填写男或女，也可留空。每次最多200名，文件不超过1MB。
- 每行填写班级；同一份名单可包含多个班级。班级按“导入教师＋班级名称”归属，不同教师的同名班级相互隔离。管理员导入的班级由管理员管理。
- 账号为姓名拼音加 `_student`。账号重名时添加数字，例如 `chenhui2_student`。初始密码为随机八位数字。
- “导出账号密码 Excel”下载 `.xlsx`，包含姓名、性别、年龄、班级、账号、密码。密码作为文本导出，避免Excel改变格式。
- 同一班级重复上传完全相同的名单不会再次创建账号。补录时使用仅含新增学生的名单。删除学生后如需恢复，请重新手动创建账号。
- 有无效行或公式时整份拒绝导入，不会只导入前半部分。
- 旧版只保存密码哈希，无法反推出原密码，导出显示“未保存”；重置密码后即可导出新密码。

## 删除与确认

- 所有删除按钮先弹出确认框，说明对象和影响；取消不会发送删除请求。
- 删除学生：删除该账号、登录会话、全部成绩和对话。
- 清除测验：清除该学生三份测验成绩，下次需要重新完成测验。
- 删除对话：只删除选中提问及其AI回答。
- 管理员删除教师：教师账号立即失效，班级及学生档案保留，由管理员管理。
- 删除不可撤销；后端独立检查权限，教师不能通过修改请求删除其他班级的数据。

## 自动分组与审核

- 只对本班启用的学生分组；全部完成三份当前版本测验后，系统生成草案。
- 使用三课总分（满分300）寻找最接近班级人数中点的分数边界；相同总分归为同一水平，不因姓名或账号把同分者强行分为高低。教师看到的是本班实际低分段、高分段及每组成员总分。
- 优先最大化同性别两人组数，再使低低、高高、高低三类组数差尽量小。性别未填写者单独处理，不猜测性别；性别人数和同分分布可能使三类数量无法相同。
- 人数为奇数时保留一名单人待补，教师能看到该状态。确认后仍生成单人小组码，避免该学生无法进入实验。
- 教师在“小组管理”查看草案并二次确认，确认后才生成八位小组码，重复确认不会更换已生成的码。
- Excel 导出只包含已确认班级的小组，含班级、小组码、组员、类型、总分及分数段。学生只能用自己所属小组的码加入，不能凭别组的码跨组进入。
- 实验页显示组号及组员姓名，加入状态重启后保留；每位学生的AI请求仍按其登录身份记录，不合并或冒充另一位组员的发言。
- 新增/删除学生、变更班级/性别/启用状态或清除测验成绩，会使相关班级分组及小组码失效。全部测验完成后重新生成草案，教师须再次审核；普通姓名或密码修改不会改变分组。
- 升级前已完成前两份测验的学生保留成绩，只补做第三份。已有教师及班级归属保留，教师现在可导入更多班级。

## 测验与记录

首次登录依次完成三份入门测验，每份10题、每题10分。服务端评分，学生页面和接口均不返回分数、答对题数或高低组类型；成绩只供教师及管理员查看。已提交成绩不能通过重复提交覆盖；三份完成后等待全班完成，教师确认分组后，学生输入本组小组码才能进入实验及调用AI。教师主动清除测验除外。

成绩和AI对话可导出XLSX，Excel可打开。对话含学生提问、AI回答、课程、环节、时间、来源和状态。`model` 为在线模型，`fallback` 为离线备用回复，`rule` 为固定流程提示。第四环节固定自评回复也会保存。学生清空页面记录不会删除教师档案。

## 存储与备份

数据库在卷内的 `school.sqlite`。登录密码使用带随机盐的 scrypt 校验。为满足管理员查看教师密码及教师导出学生密码的需求，新密码另以 AES-256-GCM 加密保存，加密密钥为同目录的 `school.sqlite.credentials.key`，不会下发学生浏览器或加入Git。

**备份和恢复必须包含整个卷，尤其是数据库和加密密钥。** 密钥丢失时不能解密已有密码，应用会拒绝启动，避免生成新密钥覆盖。运行中不要只拷贝SQLite主文件，WAL日志可能含未合并写入；使用Railway卷备份或停服后备份整个目录。

重新部署保留卷内记录；删除或更换卷不会迁移数据。会话12小时过期；重置账号或密码、停用账号、删除账号使对应会话失效。

## 本地验证

安装Node.js 24及pnpm，执行 `pnpm install --frozen-lockfile`。复制 `.env.example` 为 `.env.local` 并填写管理员凭据，默认数据目录 `./data` 已忽略。

```sh
pnpm start
pnpm check
pnpm test
```

测试使用临时数据库，覆盖角色与班级隔离、旧库迁移、密码重置、Excel导入导出、删除权限、三份测验顺序、评分及AI完整对话保存。题库答案仅保存在服务端 `quizzes.json`；公开接口剔除答案。

## 历史班级归属

旧账号仍保留在原班级，不会因教师注册或同名班级自动转移。管理员在“教师账号 → 班级归属”选择教师并确认分配，原学生账号、测验及对话保持不变。教师账号全局不可重名；导入的同名学生按姓名拼音加序号生成唯一账号，班级信息独立保存。

成绩和对话导出为真正的 `.xlsx` 文件，按钮位于管理导航栏。
