# 学生登录、入门测验与教师管理部署

## Railway 升级前准备

1. 为现有应用服务添加 **Volume**，挂载路径填写 `/data`。必须关联到运行本应用的服务。
2. 在该服务的 Variables 中设置 `TEACHER_USERNAME` 和 `TEACHER_PASSWORD`。密码至少 12 位；不要把密码写入 GitHub。
3. 保留原有 `DEEPSEEK_API_KEY` 等变量。使用仓库中的 `Dockerfile` 构建，运行 Node.js 24。健康检查地址为 `/health`。
4. 完成以上配置后部署新代码。保持单个应用实例；此版本使用挂载卷中的 SQLite，不适用于多个副本分别挂载独立磁盘。
5. 打开网站，用教师账号登录，再创建学生账号。

Railway 会自动注入 `RAILWAY_VOLUME_MOUNT_PATH`，应用在该目录创建 `school.sqlite`。**不要手工伪造该变量来跳过挂载卷**。缺少持久卷时，Railway 环境会拒绝启动，防止在临时磁盘上接受真实学生数据。

参考：[Railway 持久卷](https://docs.railway.com/volumes)、[Dockerfile 构建](https://docs.railway.com/builds/dockerfiles)。

## 日常使用

- 教师和学生共用网站登录页，服务端依据账号身份进入相应界面。
- 教师创建或编辑学生的姓名、性别、班级、账号和密码，也可以停用账号。密码使用带随机盐的 scrypt 哈希存储，不能查看原密码；需要时可重置。
- 首次登录的学生先完成第一份测验，再完成第二份。每份 10 题，每题 10 分。刷新会保留本浏览器标签页中的未提交选项，提交后成绩保存到服务器。
- 已提交成绩不能通过再次提交覆盖；下次登录直接进入实验。两份完成前，服务端也会阻止调用实验配置和 AI 接口。
- 学生端实验区域顶部显示当前账号及退出按钮。课堂共用设备应先退出，再换另一个账号登录。
- 教师在“测验成绩”查看每名学生两份测验完成情况并导出 CSV；在“AI 对话记录”按学生筛选、分页查看并导出对话。
- 导出文件含 UTF-8 BOM，可用 Excel 打开。对话包含学生原文、AI完整回答、课程、环节、时间和来源。`model` 表示在线模型，`fallback` 表示离线备用回复，`rule` 表示固定流程提示。
- 第四环节采用固定自评回复，也会保存；请求尚未返回、失败或被重启打断都有对应状态。

## 数据与备份

数据库保存账号、登录会话、原始作答、成绩和对话。会话 12 小时过期；修改学生账号或密码会撤销该学生现有会话。

重启、重新部署不改变已挂载卷中的记录。**删除或更换 Volume 会丢失原卷中的数据**。请在 Railway 设置卷的备份，并定期导出成绩与对话。运行中不要只拷贝 `school.sqlite` 一个文件，因为 WAL 日志可能仍有未合并数据；使用 Railway 卷备份，或停服后一起备份数据库及同目录 WAL 文件。

初始化变量仅在数据库没有教师账号时创建教师。后续修改 `TEACHER_PASSWORD` 不会重置数据库中的既有教师密码，避免无意覆盖账号。

本版不导入升级之前仅存于浏览器中的匿名会话；新登录体系中的请求才会关联到实名学生。清空学生端当前实验记录不删除教师端档案。

## 题库维护

- `quizzes.json` 是服务端题库，包含题目、选项、配图引用及答案；不位于静态公开目录。
- `public/quiz-images/` 保存从两份原始 Word 中提取的配图。
- `scripts/import-quizzes.py` 可从原始文件目录重新导入。修改题目或评分标准时更新题库 `version`，避免与旧成绩混淆。
- `/api/quizzes` 仅向已登录用户返回移除答案的题目，成绩由服务端计算，忽略客户端提供的分数或学生ID。

## 本地开发与验证

需要 Node.js 24。将 `.env.example` 复制为 `.env.local` 后设置教师账号密码；默认数据库目录为 `./data`，已被 Git 忽略。

```sh
npm start
npm run check
npm test
```

自动测试使用临时数据库和测试账号，不接触正式学生档案。涵盖登录、权限隔离、提交顺序、服务端计分、防覆盖、配图与答案隔离、AI对话留存、CSV导出、密码重置和数据库重新打开后的持久化。
