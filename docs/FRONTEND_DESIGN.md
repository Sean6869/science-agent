# 前端设计说明

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2 |
| 依据 | PRD v0.2、用户提供的 HTML 布局参考与 PhET 外部实验页面 |
| 设计目标 | 清晰、轻量、适合初中学生课堂操作的实验工作台 |

## 1. 设计原则

- **实验优先**：左侧实验可视面积最大，学生先观察再求助。
- **过程可见**：右侧六阶段始终可定位当前探究进展，倒计时与聊天历史保留任务节奏和思考轨迹。
- **低认知负担**：按钮和文案清晰、字号可读，避免把信息挤成小胶囊按钮。
- **反馈明确**：第三方加载、保存、发问、生成、失败均有即时状态。
- **可信引导**：Agent 只引用学生报告的 PhET 实验观察，不把未获得的第三方页面状态表现成事实。

## 2. 结构参考与外部实验

### 2.1 继承的视觉方向

- 柔和蓝色课堂科技感背景和白色圆角卡片。
- 左大右小的横向布局。
- 实验区的浅暖色背景，用于区分操作空间。
- 学生消息使用主色气泡、Agent 消息使用浅灰/白色气泡。

### 2.2 必须改进的部分

| 原型元素 | 新设计 |
| --- | --- |
| 右侧高度被表单占用较多，聊天可视区仅约 380px | 表单默认紧凑，可折叠；聊天作为右栏主要伸展区 |
| 五按钮字号约 `0.7rem` 且横向拥挤 | 使用垂直步骤列表或两列卡片，正文至少 `14px` |
| `user-select: none` 作用到整页 | 主应用聊天文本支持选取；PhET 内部行为由第三方页面决定 |
| 教师/先验知识文案 | 学生友好且隐私最小化的试验者信息 |
| 原型自行绘制实验区域 | 不实现该区域；左侧 iframe 直接加载 PhET 具体凸透镜资源页 |

### 2.3 外部资源地址

| 配置 | 地址 | 设计使用方式 |
| --- | --- | --- |
| 平台入口 | [https://phet.colorado.edu/zh_CN/](https://phet.colorado.edu/zh_CN/) | 维护时查找其他实验，不作为课堂默认页 |
| 目标实验资源 | [https://phet.colorado.edu/sims/html/geometric-optics/latest/geometric-optics_zh_CN.html?screens=1](https://phet.colorado.edu/sims/html/geometric-optics/latest/geometric-optics_zh_CN.html?screens=1) | iframe 直接加载中文“几何光学”的透镜屏幕 |

## 3. 桌面页面布局

### 3.1 整体框架

目标视口：`1440 x 900`，最低主要支持：`1280 x 720`。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 顶栏  凸透镜探究实验室                    当前阶段 / 会话状态 / 帮助          │
├──────────────────────────────────────────────┬──────────────────────────────┤
│                                              │ 试验者信息卡（可折叠）        │
│ 左侧实验卡（约 60%）                         ├──────────────────────────────┤
│ ┌──────────────────────────────────────────┐ │ 探究步骤导航                 │
│ │ iframe：PhET 凸透镜实验资源页           │ │ ①观察 ②假设 ③设计 ④采证 ⑤评估│
│ │ 学生在第三方页面中进入并操作实验          │ ├──────────────────────────────┤
│ └──────────────────────────────────────────┘ │ 对话记录（伸展与滚动）        │
│ 提示：请将观察到的现象或数据告诉小科         │                              │
│                                              ├──────────────────────────────┤
│                                              │ 输入框                 发送   │
└──────────────────────────────────────────────┴──────────────────────────────┘
```

### 3.2 网格规格

| 区域 | 推荐值 |
| --- | --- |
| 页面最大宽度 | `1440px` |
| 页面外间距 | 桌面 `24px`，小屏 `12px` |
| 左右栏比例 | `minmax(560px, 1.55fr) minmax(400px, 1fr)` |
| 两栏间距 | `16px` |
| 卡片圆角 | `20px` |
| 卡片内边距 | `16px` 或 `20px` |
| 顶栏高度 | `56px` |
| 右栏可用高度 | `calc(100vh - 48px)`，对话区吸收剩余高度 |

## 4. 响应式设计

| 断点 | 布局行为 |
| --- | --- |
| `>= 1180px` | 固定双栏；实验与对话同时可见 |
| `768px - 1179px` | 双栏但右栏宽度不低于 `360px`；表单默认折叠摘要 |
| `< 768px` | 单栏；实验在上，对话在下；步骤变为横向可滚动分段控件 |

课堂核心体验以横屏电脑/平板为准。手机布局用于可访问降级，不作为复杂实验的主要操作终端。

## 5. 页面区域设计

### 5.1 顶栏 `AppHeader`

| 内容 | 说明 |
| --- | --- |
| 标题 | `凸透镜探究实验室` |
| 副状态 | 当前步骤，例如 `第 2 步：提出并确认假设` |
| 操作 | `重新开始`（二次确认）、`使用帮助` |

顶栏保持克制，不放置教师后台入口或模型技术信息。

### 5.2 实验卡 `ExperimentPanel`

| 子区域 | 内容与行为 |
| --- | --- |
| 标题区 | 显示“小科”品牌和课程切换与支架开关 |
| iframe 容器 | 直接加载 `PHET_GEOMETRIC_OPTICS_URL`；使用 `title="PhET 几何光学凸透镜实验"` |
| 观察提示条 | 显示 `完成操作后，请把观察到的现象或数据告诉小科` |
| 空/故障态 | 页面无法加载时提示重试，提示检查网络后刷新页面 |

**嵌入约束**

- iframe 只加载白名单 `https://phet.colorado.edu/sims/html/geometric-optics/` 下的 HTTPS 页面，不代理或复制 PhET 页面内容。
- PhET 页面为跨域第三方页面，主应用不读取其 DOM，不假定存在实验状态事件。
- 在实现验收时检查透镜屏幕交互、学校网络加载和页面刷新恢复。
- iframe 不接触 Agent API 凭证和学生会话令牌。

### 5.3 试验者信息卡 `ParticipantCard`

默认展开于首次进入；保存后收起为摘要行，提供“编辑”按钮，避免挤压聊天空间。

| 字段 | 类型 | 是否必填 | 文案/规则 |
| --- | --- | --- | --- |
| 班级或任务编号 | 文本 | 否 | `例如：八年级 2 班 / 任务 A` |
| 小组编号 | 文本 | 是 | `例如：第 1 小组` |
| 成员 1 昵称 | 文本 | 是 | `请输入成员昵称` |
| 成员 2 昵称 | 文本 | 否 | `可选` |

| 状态 | UI 表达 |
| --- | --- |
| 初始 | 说明“信息仅用于本次实验中的称呼与协作引导” |
| 验证失败 | 字段下方错误说明，焦点移至首个错误 |
| 保存成功 | 摘要 `第 1 小组：小明、小华` 和编辑入口；聊天显示简短确认 |

不在学生表单中暴露“低/高先验知识学习者”的选择。

### 5.4 探究步骤 `InquirySteps`

右侧采用六个等宽阶段节点、连接线和双行标签。节点下方放置当前环节倒计时与可收起的教师时长设置；窄屏保持标签可读并允许页面纵向排布。

| 状态 | 视觉 |
| --- | --- |
| 未开始 | 中性边框，深灰标题 |
| 当前阶段 | 蓝色填充/左侧标识线，显示 `当前` 文本或图标 |
| 已访问 | 轻蓝背景和勾选标记 |
| 聚焦 | 2px 明确焦点环 |

按钮文案：

| 顺序 | 短标签 | 完整辅助名称 |
| --- | --- | --- |
| 1 | 观察问题 | 共同观察与问题界定 |
| 2 | 提出假设 | 提出并确认假设 |
| 3 | 设计实验 | 协作设计实验 |
| 4 | 采集证据 | 协作采集证据 |
| 5 | 评估证据 | 协作评估证据并得出结论 |
| 6 | 反思讨论 | 反思讨论 |

**点击交互**

1. 暂停上一阶段倒计时，切换并启动当前阶段倒计时。
2. 更新开场白并播放当前阶段预生成教师语音。
3. 保留各阶段独立草稿、正式提交、星级自评和反馈历史。
4. 正式内容提交后，Agent 按当前量规返回“引导自评、参考星级、反馈评语”。

### 5.5 聊天区 `AgentChat`

| 元素 | 设计 |
| --- | --- |
| 欢迎消息 | 说明 Agent 是“小科”科学探究智能学伴，建议先观察左侧再选择步骤 |
| 用户消息 | 主色气泡，右对齐；步骤触发消息带阶段徽标 |
| Agent 消息 | 浅色卡片，左对齐；保留引导自评、参考星级、反馈评语三段换行 |
| 状态消息 | `正在思考怎样引导你观察...`，提供停止/重试能力视接口实现决定 |
| 错误消息 | 明确说明未发送成功，按钮 `重新发送` |
| 输入区 | 多行文本输入；`Enter` 发送、`Shift + Enter` 换行；发送按钮 |

聊天内容必须允许文本选择，不继承参考原型的全局 `user-select: none`。

## 6. 视觉系统

### 6.1 色彩建议

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#EEF5FB` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 右侧与通用卡片 |
| `--color-lab-surface` | `#FFFDF1` | 实验卡背景 |
| `--color-primary` | `#2563EB` | 主按钮、选中阶段、学生气泡 |
| `--color-primary-soft` | `#E8F0FF` | 已访问阶段、摘要底色 |
| `--color-text` | `#0F172A` | 主文本 |
| `--color-muted` | `#64748B` | 辅助文字 |
| `--color-border` | `#D8E2EE` | 分隔与输入框 |
| `--color-success` | `#15803D` | 成功和虚像说明的辅助标记 |
| `--color-warning` | `#B45309` | 特殊成像或注意提示 |
| `--color-error` | `#B91C1C` | 验证与网络错误 |

不得仅依赖红/绿区分像性质，应始终显示文字 `实像`、`虚像` 或 `无法得到清晰像`。

### 6.2 字体与层级

字体栈：`"Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`。

| 样式 | 字号/行高 | 用途 |
| --- | --- | --- |
| 页面标题 | `22px / 30px`, semibold | 顶栏标题 |
| 卡片标题 | `17px / 24px`, semibold | 区域标题 |
| 正文 | `14px / 22px` | 消息与表单 |
| 辅助文字 | `12px / 18px` | 状态提示 |
| 按钮 | `14px / 20px`, medium | 所有可点击主要文本 |

### 6.3 间距与动效

- 使用 `4, 8, 12, 16, 20, 24, 32` 的间距刻度。
- hover/选中变换控制在 `120-180ms`；避免学生误以为实验状态正在变化。
- 生成中可显示轻量脉冲点，不使用分散注意力的动画。

## 7. 组件与工程结构建议

推荐技术栈：`React + TypeScript + Vite`，Agent 通过独立服务端端点接入。

```text
src/
  app/
    App.tsx
    AppLayout.tsx
  features/
    experiment/
      ExperimentPanel.tsx
      externalLabConfig.ts
    participants/
      ParticipantCard.tsx
      participantSchema.ts
    inquiry/
      InquirySteps.tsx
      stepPrompts.ts
    chat/
      AgentChat.tsx
      MessageList.tsx
      ChatComposer.tsx
      chatApi.ts
  shared/
    components/
    styles/
    types/
```

| 组件 | 职责 | 关键输入/输出 |
| --- | --- | --- |
| `AppLayout` | 双栏布局及响应式排列 | 页面组合 |
| `ExperimentPanel` | PhET 几何光学 iframe、加载提示与备用打开操作 | 输出加载状态 |
| `ParticipantCard` | 表单校验及摘要 | 输出 `participantContext` |
| `InquirySteps` | 渲染六阶段、倒计时和时长设置 | 输出 `activeStep`, `timers` |
| `AgentChat` | 会话编排及 API 调用 | 输入上下文、输出消息 |
| `MessageList` | 消息呈现、滚动和错误状态 | 消息数组 |
| `ChatComposer` | 用户自由输入 | 发送事件 |

### 7.1 状态边界

```ts
type WorkspaceState = {
  participants: ParticipantContext | null;
  activeStep: InquiryStep | null;
  visitedSteps: InquiryStep[];
  messages: ChatMessage[];
};
```

- `ExperimentPanel` 只负责加载第三方实验与显示故障恢复，不负责聊天业务或读取实验状态。
- `InquirySteps` 从集中定义的提示词读取文本，组件内不散落大段字符串。
- `AgentChat` 负责构造请求与处理网络状态；观察数据来自学生消息，不直接修改或读取 iframe。
- 首版可使用 React state/context；不为有限页面过早引入复杂状态库。

### 7.2 Agent 接口建议

```http
POST /api/chat
Content-Type: application/json
```

请求使用 PRD 中的 `AgentRequest`，响应建议为结构化消息：

```ts
type AgentReply = {
  messageId: string;
  content: string;
  relatedStep: 1 | 2 | 3 | 4 | 5 | null;
  createdAt: string;
};
```

实现流式返回前先完成稳定的非流式 MVP；若采用流式输出，仍需保留失败恢复和内容安全处理。

## 8. 可访问性与学生体验检查

| 检查项 | 要求 |
| --- | --- |
| 键盘顺序 | 顶栏 -> PhET iframe -> 表单 -> 阶段 -> 消息输入；主应用顺序符合视觉结构 |
| 焦点样式 | 主应用按钮与输入均可见焦点环；PhET 内部可访问性另行验收并记录限制 |
| 语义 | 使用 `header`, `main`, `section`, `form`, `button`；聊天使用可理解的消息列表语义 |
| iframe | 提供准确 `title` 与加载失败备用入口；第三方控件标签属于供应方页面能力 |
| 动态通知 | 保存成功、API 错误和新 Agent 回复可由 `aria-live` 适度播报 |
| 表述 | 采用“尝试观察”“你发现了什么”，避免评价学生能力 |

## 9. 页面状态清单

| 状态 | 页面必须呈现 |
| --- | --- |
| 首次进入 | PhET 实验资源页 iframe、展开的信息表单、欢迎消息、未激活步骤 |
| 已保存信息 | 折叠摘要、可编辑按钮、会话确认消息 |
| 选中步骤 | 当前步骤样式、触发请求消息、Agent 生成态 |
| Agent 成功回复 | 新消息与下一项可执行观察任务 |
| Agent 失败 | 错误卡片、重试按钮、输入内容未丢失 |
| 实验未加载 | 左侧错误提示、刷新提示，右侧仍可说明问题 |
| 学生报告 `u = f` | Agent 根据学生消息解释该情形，不宣称自动检测了 PhET 状态 |

## 10. 设计验收清单

- 左侧加载指定 PhET 凸透镜资源页，不包含自行实现的模拟器代码。
- 右侧在 `1280 x 720` 中仍能看到输入框，聊天可滚动。
- 六个阶段均可清晰阅读，倒计时位于阶段条下方，时长设置默认收起。
- 表单不默认展示真实学生姓名或能力标签。
- Agent 不自动读取 PhET 状态；观察信息明确来源于学生输入。
- 所有主要交互可通过键盘完成，聊天文本可选择。
- Agent 失败、实验失败和空表单均有可恢复反馈。
- 在部署网络中核验 PhET 嵌入、透镜屏幕交互和加载速度。
